# Named exercises are backed by a shared, separately-persisted template library, copied by value into Sets

To satisfy "name an exercise once, reuse it in other workouts" (#4), we introduce a flat, persisted list of exercise templates — each a `{name, default duration, default reps}` — independent of any workout or Set. Adding an Exercise to a Set offers picking an existing template (copying its fields onto the new `TimedExercise`) or starting blank. The copy is by value: editing the exercise's duration/reps/name within one Set's instance never changes the template or any other Set's exercise that was copied from the same template, and editing the template itself does not retroactively change exercises already created from it. The alternative was a live reference from `TimedExercise` to a shared template object, so all copies update together.

Picked copy-by-value because it matches the existing `clone()` semantics already used for Set/Exercise duplication, and avoids a new class of "spooky action at a distance" bug where editing one workout's exercise unexpectedly changes another saved workout's history. The cost is template drift — templates and their copies can diverge over time — which is accepted as the normal, expected behavior (a template is a starting point, not a binding).
