# Render the editor as a nested layout of Sets, not a flat ListView with synthetic header rows; rebuild reordering scoped to within-Set and Set-level only

`FirstPage.qml` today is one `SilicaListView` over a flat `TimedExercise` list, with Silica's built-in drag-reorder (`moveItems`/`copyItems`) operating on flat indices. We're replacing it with a nested layout — an outer list of Set "cards," each containing its own inner list of Exercise rows and its own add/delete controls — that mirrors the tree model directly (ADR-0002), rather than flattening the tree into one `ListView` with synthetic "set header" rows interleaved among exercise rows.

Picked the nested layout because it needs no synthetic row types kept in sync with the model, at the cost of losing Silica's built-in single-`ListView` drag-reorder for free — reordering has to be rebuilt. We're rebuilding it scoped to two operations only: reordering Exercises within a Set, and reordering Sets relative to each other. Moving an Exercise from one Set into another is deliberately out of scope for now — it's the most complex case (the drag target spans two visual containers) and not essential, since the same result is achievable today via delete-and-re-add. Duplication (`copyItems`) extends to both levels: duplicating an Exercise within its Set, and duplicating a whole Set (with its children and `rounds` value).
