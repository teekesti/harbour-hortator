# First-use hints re-derive from the empty-draft condition on every launch, not a persisted one-time flag

First-use interaction hints (#14) are gated by a new transient `ExerciseTimer::showFirstUseHints` property, set to `true` in `harbour-hortator.cpp`'s existing `if (model->isEmpty())` branch — the same branch that seeds the default Set/Exercise the Draft starts from. No value is written to `QSettings`; the condition is simply recomputed at every app launch. The alternative was a persisted "hints already shown" boolean, written once the first time it fires and checked (and never reset) on every subsequent launch, regardless of Draft state.

Picked recomputation over persistence because the two would only ever differ in one case — a returning user who deletes every Set, so the Draft is re-seeded back to the same one-Set/one-Exercise default a genuine first launch starts from — and in that case showing the hints again is correct, not a bug: the three v1 hint targets are on screen either way, in exactly the state the hints describe, so there is no reason to distinguish "never seen this screen before" from "looking at this screen's default state again." Tying the property to the pre-existing `isEmpty()` check also means no new `QSettings` key, no migration concern, and no separate "reset onboarding" affordance to maintain.
